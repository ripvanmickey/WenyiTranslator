# YouTube 视频字幕预加载（测试功能）

从首页底部输入选择器的「媒体」进入，配置区在首页右侧展开。视频继续在 Chrome 或 Safari 播放；文译读取当前视频的媒体时间显示字幕，不录制系统声音，不使用录音经过时间模拟播放进度。

## 提前播放（1.16.5 测试版）

- 已有／导入字幕：边翻译边播放，已准备的段落立即可用。
- OpenAI 音轨识别：首次仍先下载完整音轨，再划分语音片段。此后识别一段、保存识别进度并翻译一段，完成后立即可播放，不再等待整条音轨识别完毕。界面显示“字幕已准备至 mm:ss”。
- 建议等待前面约 30～60 秒字幕准备好再播放，给后续处理留出余量；这只是播放缓冲建议，不保证任何网络或视频下均能持续跟上。浏览器仍由你手动播放／暂停。
- 若播放超过已准备范围，该位置可能暂时没有译文；可以暂停等待后续字幕。字幕按媒体时间同步，不会把尚未准备好的字幕提前错配到当前位置。

## 使用

1. 输入 HTTPS YouTube 视频链接，选择原文、译文和翻译模型。
2. 字幕来源默认是“YouTube 已有字幕”。也可导入 UTF-8 SRT／VTT；文件的时间轴须对应此视频。
3. 没有字幕时，可主动选择“OpenAI 音轨识别 · 云端”。点击“开始预加载”后，公开音轨的语音片段才会发送到 OpenAI `gpt-transcribe`。识别使用片段时间轴，不承诺逐词强制对齐。API 权限、余额和网络要求适用。
4. 翻译可选择 Index 在线翻译或 OpenAI GPT-4.1 mini。已有／导入字幕只发送字幕文字；音轨识别模式另外发送音频片段。开发检查不自动读取真实密钥或调用付费 API。
5. 首次连接时将目标 YouTube 视频切为当前标签页，点击“连接当前视频”，允许文译访问所选浏览器。连接后文译跟随原视频，进出全屏短暂失败时自动恢复。点击首页顶部的字幕按钮显示或隐藏可移动、可调整大小的字幕窗。悬浮字幕原文白色，译文黄色。
6. 在浏览器暂停、拖动或改变倍速，字幕按实际媒体时间重新定位。识别到广告或切换到另一个视频时隐藏字幕。广告检测取决于 YouTube 页面标记，页面升级后可能需适配。

## 浏览器连接

文译通过 Apple Events 读取关联 YouTube 视频的播放时间、暂停状态、倍速及广告状态。只有点击底栏播放／暂停或使用对应快捷键时，才控制关联视频的播放状态；不会读取或导出浏览器 Cookie，也不读取其他网站的正文。

- Chrome：在“显示 → 开发者”开启“允许来自 Apple 事件的 JavaScript”。
- Safari：在“开发”菜单开启“允许来自 Apple 事件的 JavaScript”。若没有“开发”菜单，在 Safari 设置的高级页启用开发者功能。
- 系统设置 → 隐私与安全性 → 自动化：允许文译访问所选浏览器。

这些设置由用户决定。应用不自动修改浏览器安全选项。未授权、浏览器关闭、标签页不匹配时，会显示连接说明并停止同步；不会反复弹权限窗口。

## 缓存与限制

- 输入视频链接、选择语言和翻译模型后自动读取匹配的本机缓存，无需再次点击预加载。完整缓存不再下载或翻译；未完成缓存可直接播放已准备部分，点击“补齐缺失字幕”仅翻译缺失段落。切换视频或配置时会重新匹配，防止使用其他视频或语言的字幕。

- 字幕及已完成译文保存在 `~/Library/Application Support/Wenyi/VideoSubtitles`，按视频、语言组合、来源和翻译模型区分，支持复用及双语 SRT 导出。
- 翻译阶段中断后可重试，复用已完成的译文。音轨识别阶段也按片段保存检查点，停止后点击“继续准备字幕”，从未完成片段继续。已保存识别结果的片段不再重复上传；文字翻译失败仅重试该段文字。临时音轨会清理，续接时可能需重新下载音轨，但不会重做已保存的识别请求。
- 临时下载音轨在任务结束／取消时清理。缓存字幕不随安装包发布，也不提交到 GitHub。
- 从公开 YouTube 获取字幕／音轨需要网络。登录限制、地区限制、YouTube 反爬或字幕不可用时，明确报错，可改为导入已有字幕。不会自动使用浏览器账号绕过限制。直播不支持预加载完整字幕；音轨识别最长 3 小时。
- 若尚未翻译到当前播放位置，先显示已准备的原文。可等待准备完成后再播放，避免译文等待。
- 此功能不改变原有实时聆听功能和语音识别默认值。

## Gemini 音轨预加载（1266）

字幕来源新增「Gemini 音轨识别 · 云端」。选择后，右侧的「配置」按钮打开 Gemini 密钥设置；翻译模型仍选择 Index 或 OpenAI。点击开始准备后，音轨按现有语音时间段切片，发送到 `gemini-3.5-transcribe`，再把文字交给所选翻译服务，会产生相应 API 用量。没有自动切换到收费备用模型的逻辑。

每段识别后先存缓存，再翻译并保存；字幕随准备随播放，暂停或失败后继续当前检查点。Gemini、OpenAI、Nemotron 的音轨识别缓存分别保存；已完成缓存不需要再次上传音频。

实时 Gemini Live 翻译同时修复分段：处理服务端 `turnComplete`，收尾当前字幕；连续长回合按原文／译文完整句子前缀分段。中断时保留收到的文本，不把未完成译文标成完成。每段保留独立字幕标识，记录按已显示的全部段落保存。

开发验证使用本地协议样例及连续文本回放，不使用用户密钥上传音频；真实 Gemini 识别效果、配额和延迟仍需在测试版中确认。

协议依据：[Live 回合边界](https://ai.google.dev/api/live)、[Gemini 音轨转写](https://ai.google.dev/gemini-api/docs/transcribe)、[Interactions 响应结构](https://ai.google.dev/api/interactions)。

本地专项验证命令：`python3 script/test_gemini_media.py --scratch-path ../macos27-preview-native-release --cache-path ../media-build-cache`（需 Xcode，模块缓存写入可写目录）。本次 45 项、4 个测试组报告通过，其中已有 Nemotron GPU 单独冒烟测试按环境跳过。脚本结束后恢复 Package.swift。
