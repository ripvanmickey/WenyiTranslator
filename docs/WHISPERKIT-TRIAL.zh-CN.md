# WhisperKit 识别试用版（build 1168）

## 使用

1. 退出旧版，解压应用 ZIP 并替换 Local Qwen 应用。默认仍使用 Apple Speech，原有本地 Qwen 翻译配置与纯音频开关保留。
2. 设置 → General → Processing Mode 选 Apple →「语音识别引擎」选「Argmax WhisperKit（实验）」。此处 Apple 表示原有本地工作流入口，实际识别可选择 WhisperKit。
3. 首先试 Base 多语言模型，点击「下载并准备模型」。首次需要联网，从 Hugging Face 下载 Core ML 模型和分词器，并完成本机加载；准备成功后才开始监听。没有 Argmax Pro 授权或 API 密钥要求。
4. 翻译引擎继续选择已配置的「本地模型翻译」（如 Qwen 35B）。本次试用支持本地模型翻译或仅转写，不支持 WhisperKit 搭配 Apple 文本翻译。英语、日语等使用主窗口选择的源语言，不进行自动语言检测。
5. 若下载失败，可选择已下载的 WhisperKit Core ML 模型文件夹。应包含 AudioEncoder、TextDecoder、MelSpectrogram 模型；LM Studio 的 Qwen / MLX 权重不能用于此处。首次分词器准备仍可能需要联网。
6. 切换引擎需要先停止监听。可随时选回 Apple Speech；错误时不会自动改用另一个识别引擎。

模型选择：Tiny 更轻量，Base 为默认试用，Small 更大。较大模型不保证更快或更适合日语，必须用同一段音频比较。

## 接入方式

复用现有系统音频 / 麦克风采集，WhisperKit 仅负责识别；不启用 SDK 自带的额外麦克风录音。输出接入已有临时字幕、最终字幕与本地 Qwen 增量翻译。纯音频 Tap 与兼容采集仍由 Audio 设置的开关独立控制。

单个识别任务串行处理，最早约 0.5 秒音频形成首个窗口；后续至少约 0.35 秒新增音频才请求更新。约 0.55 秒低能量音频触发最终结果，连续语音按最长约 12 秒分段。实际输出还需要模型运算时间，这些数值不是实际出字延迟承诺。暂未接入解码 token 级显示，识别完成当前窗口后显示可修订文字。

处理期间继续接收音频，完成旧窗口时保留新到达音频；超过 20 秒缓冲时明确停止报错，而不是无限堆积识别任务。暂停清空当前未完成音频并使旧结果失效；停止、切换和重新开始时检查任务身份，避免旧识别覆盖新会话。识别主要使用 CPU / Neural Engine，SDK 默认的频谱处理可能使用 GPU，不能保证与大语言模型同时运行时没有资源竞争。

## 测试范围

- 从用户提供的 Argmax / Apple 官方源码 ZIP 本地编译，发布构建成功；未修改第三方推理源码。Argmax 两份 Package manifest 的 ArgumentParser 依赖改为相邻本地目录。
- 音频适配检查通过：16kHz 单声道 Float32 与 Int16 输入，转换后采样数和幅度正确。
- 调度检查通过：首窗与更新阈值、无新增音频不创建重复任务、静音最终结果、保留解码期间新音频、暂停后丢弃旧结果、静音缓冲和 20 秒过载边界。
- 缺少模型时清晰失败，未启动采集时停止 / 暂停安全。
- 打包后解压验证签名和 build 1168。

尚未验证：实际模型权重加载后的英语 / 日语识别准确率、首段速度、持续播放延迟、与 35B 同时运行的性能，以及新界面的实机点击流程。源码 ZIP 不含识别权重，本次没有可报告的真实 WhisperKit 识别速度数据，不能声称已超过 Apple Speech。

可运行 `bash script/verify_whisper.sh` 重现编译与不依赖权重的音频/调度检查。SDK 上游有废弃 API 与 Sendable 提示，本次发布编译没有因此失败。

## 对照测试

先保持纯音频开关关闭，用同一段普通英语或日语视频分别测试 Apple 与 WhisperKit，模型准备及预热完成后再采样。General → 延迟诊断会显示识别引擎与采集方式；每轮清空样本，播放相同片段约一分钟，保存报告并记录原文出字感受。之后再独立测试纯音频开关，避免混淆两个变量。

WhisperKit 诊断使用音频能量估算语音末端；Apple 的识别范围由系统给出。两者并非人工标注的相同语音终点，数字不能替代真实音频对齐对照。采集层等待仍可能未完整计入。
