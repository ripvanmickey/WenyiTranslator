# 文译 1.16.0（1173）· WhisperKit 确认与滑动窗口

## 本次改动

保留 Small / Base / Tiny 与本地 Qwen 翻译选择、纯音频采集开关以及清新版图标。识别不再只等静音或窗口填满才有机会推进：连续两次识别的前段文字一致、时间位置相近（差异不超过 0.2 秒），且距离输入末尾至少 0.8 秒时，会确认这些完整片段并移出音频窗口；末尾继续作为临时识别修订。

确认前段和临时尾部按顺序送达主界面。已经移出的前段不再交给后续识别；新到达音频保留。主界面原文标题区分「已确认」和「临时识别」，确认片段建立为独立记录。两次结果一致并不证明正确，因此模型误识别也可能被确认保留，这是降低重复计算与允许修订之间的取舍。

确认后保留的尾部已被识别并显示，不会在没有新音频时立即原样再算一遍。处理过慢时按上次推理耗时调整新增音频门槛（350–900 ms），保持单个解码任务，不堆多个重叠识别任务。

对没有有效结果或时间范围的输入继续保留，并允许上下文从默认 8 秒扩至最多 12 秒，以免一直重试完全相同的前 8 秒；相同边界的输入不会反复空算。未得到可靠结果的输入不会被强行删除。20 秒待确认音频上限没有扩大；持续无法推进时仍会明确停止。

## 诊断报告

General → 延迟诊断，每秒刷新并可复制。新增 WhisperKit 数字指标：

- 当前正在执行的识别耗时（可看到 SDK 是否一直未返回）。
- 已接收、已推进、当前待确认和待确认峰值，单位为音频秒。
- 完成的识别次数、最近及累计计算耗时。
- 累计送入模型的音频秒数（包括复算，不能当成唯一音频时长）。
- 稳定前缀确认次数、空结果次数、连续未推进次数、当前更新门槛和窗口上限。

这些指标每次开始监听重置；停止或触发上限后仍保留最后的数字报告。清空原有延迟样本不会改变音频窗口；需要独立运行对照时，停止再重新开始。诊断不增加音频、字幕文本或密钥的记录。

正常情况下，「已推进」应持续增长，待确认音频应上下波动而不是一直增长。临时尾部本来就可能尚未确认，所以“待确认音频”不等于模型还没有识别过它。若“当前识别尚未返回”不断增长，需检查模型推理；若多次识别完成但位置不动，需检查片段确认及结果时间范围。

## 已验证

- 发布编译与应用解压后的严格签名校验。
- 合成连续输入 300 秒，模拟识别器返回稳定的一秒片段：确认 299 个顺序片段，无重复，保留一秒临时尾部，测试中待确认音频峰值两秒。
- 两次一致的前段可提前推进；发生修正的前段不被确认；变化尾部继续保留。
- 确认后没有新输入时不立即重算同一尾部；空结果保留输入并等待新音频，上下文可扩展。
- 原有音频格式、模型缺失提示、短窗解码参数、暂停失效、尾部保留和 20 秒边界检查。

上述 300 秒是合成输入与模拟识别结果的窗口管理测试，不是 Small 连续识别五分钟的性能证明。本次未完成真实 Core ML 音频推理对照，仍受此前环境缓冲区限制；未进行新界面的点击测试。不能据此承诺实机不积压、没有漏字或超过会议软件的实时性能。

## 测试建议

退出旧版，解压运行新的文译.app。选择 Small 或原先用的模型，保持同一视频、语言与纯音频开关；模型文件和翻译配置不需要重新设置。连续播放约三分钟，观察原文是否持续前进，再复制「延迟诊断」完整报告。

此版继续优先使用 CPU / Neural Engine 编码和解码；频谱处理可能使用 GPU，Qwen 也使用共享内存，未宣称资源完全隔离。此次优先优化重复处理与确认机制，没有增加并行识别任务。

交付为 macOS 26+ Apple Silicon 应用 ZIP，ad-hoc 签名，未经 Apple 公证。应用标识和原模型目录沿用，源码含本地 SDK 依赖及许可证。
