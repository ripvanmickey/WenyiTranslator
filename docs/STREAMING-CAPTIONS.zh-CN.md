# 流式字幕版本 · build 1165

## 改动

- 本地 Qwen 翻译使用 SSE 流式请求，首批译文到达即更新主窗口与悬浮字幕，不再等完整段落结束。
- 保留原生接口关闭思考、8192 上下文和短段截断重试逻辑；兼容接口也支持流式解析。
- 只有明确收到完成标记才把结果认定为完成，流中断、输出截断、错误事件不会作为完整译文保存到翻译缓存。保留既有请求身份、源文字修订和取消检查，过时结果不会覆盖新字幕。
- 本地翻译模式下，短识别片段的稳定等待从 700 ms 降为 250 ms；非最终更新节奏从 300 ms 调为 250 ms。长字幕识别结果合并的间隔从 250 ms 降至 60 ms，本地模式跳过长字幕显示额外节流。
- 原本已有 Apple Speech volatile 中间结果支持，未更换识别模型或调整系统识别引擎。若 Apple 自身在音频之后约 1 秒才产出结果，本次应用层优化无法保证消除这段等待。
- General 的两个翻译测试也使用流式调用，并显示从提交文本请求开始到首段译文、完整译文的耗时。这不包含语音识别耗时，不是端到端字幕延迟。

## 检查

独立检查通过：原生与兼容 SSE；完成之前显示中间译文；思考事件和跨包思考标签不进入字幕；传输提前断开不会被视为完成；截断错误；原有本地地址、密钥隐藏、配置、分段和取消检查。识别策略检查确认短片段在 250 ms 后可提交，其他引擎仍保持原有等待；源文修正后旧译文会被拒绝。完整项目的 Swift Testing 套件在当前工具链下仍不可用。

独立 AirTranslate Streaming Test 验证副本，27B 日语到简体中文长句单次测试：首段 0.62 秒，整段 5.21 秒，已实际观察到完成前的中文逐步输出。单次文本测试不是稳定性能承诺；实际速度受模型加载、文本长度、其他客户端排队和系统负载影响。

没有启动屏幕、系统音频或麦克风录制，尚未进行实播音频到字幕的延迟对照测试。35B 初次验证被其他客户端的 27B 请求干扰；停止其他采集客户端后重试成功。35B 第一次切换加载的首段为 10.01 秒、完成 10.87 秒；模型加载后再次运行同一长句，首段为 0.50 秒、完成 1.50 秒。这些是单次文本测试，不能推断实时字幕端到端延迟。

## 安装与复测

退出旧版，解压 AirTranslate-1.16.0-Local-Qwen-stream-arm64.app.zip，用其中同名 AirTranslate Local Qwen.app 替换应用程序中的旧版。保留已有本地服务地址和模型选择。在 General 先运行「测试翻译」或「测试长句翻译」，观察首段与完整耗时，再播放同一段视频比较实际字幕。

当前包为 Apple Silicon、本机 ad-hoc 签名，未经过 Apple 公证。应用标识保持不变，系统可能需要重新确认录制权限。
