# WhisperKit 空结果中断修复（build 1170）

针对 1169 的“WhisperKit 未能确认这段含声输入，已停止”提示。该提示来自应用主动停止识别，不足以据此认定整个应用崩溃。

## 原因与修复

SDK 的 TranscribeTask 按 windowClipTime 排除末端音频，默认值为 1 秒；应用首窗最短只有 0.5 秒。短于该默认值的输入可能根本不进入 SDK 的解码循环，产生空结果，1169 又把空的最终结果一律当作致命错误。

1170 显式使用 windowClipTime=0，使短实时窗口能够进入解码。关闭 SDK 内部按 noSpeechThreshold 丢弃结果的步骤，保留片段的非语音概率，由应用区分处理：

- 有明确片段、且所有片段非语音概率至少 0.8：最终窗口按模型非语音判定正常略过，不触发致命错误。
- 空结果、没有明确概率或文字时间范围尚无效：保留输入；至少再到达 0.35 秒新音频后重试，不对同一空输入持续空转，也不将其当作已完成清除。
- 已识别有效的结果仍按覆盖时间消耗音频，沿用 1169 的未识别尾部保留与模型型号 / 文件完整性检查。

这不是忽略所有错误。文件加载失败、SDK 真正抛出的异常、超过 20 秒缓冲的持续过载等仍会明确停止。非语音判定也可能误判，不能保证模型不漏识别。

## 验证

发布编译通过；检查实际生成的 DecodingOptions：windowClipTime 为 0、noSpeechThreshold 为 nil。增量窗口回归覆盖：空结果保留音频、没有新音频时不重复尝试、追加 0.35 秒后可重试、明确非语音必须有非空概率证据；先前的尾部保留、暂停失效、过载与音频格式检查继续通过。应用 ZIP 解压后严格签名校验通过。

当前测试环境仍无法完成 Core ML 实际音频推理，因此本版没有新的真实识别速度、准确率或连续播放稳定性结论，也未进行新界面的点击测试。保留此限制，不将代码回归检查表述成实机识别验证。

## 使用

退出旧版，解压替换应用，再启动。现有权重、配置与模型缓存保持原目录，不必重复下载完整模型。先选择已经完整下载的 Base 测试同一段视频；若选择 Small，须等待 Small 自己的文件完整并准备成功，不用 Base 文件夹代替。

这是 macOS 26+ Apple Silicon 的 ad-hoc 签名应用 ZIP，未经 Apple 公证。
