# WhisperKit 音频保留与模型选择修复（build 1169）

## 本次发现

用户反馈较大识别模型运行时中间文字先消失、后来逐渐不再补回。检查时，本机偏好显示模型选项为 Small，但实际保存路径为 openai_whisper-base；Small 文件夹缺少 MelSpectrogram 核心文件等必要内容。因此此前的运行不能当作 Small 的有效速度或漏字测试。此说明不包含原文或录音。

同时，旧实现虽然保留了解码期间新到达的音频，却在最终结果返回时清除整个旧输入窗口，没有核对结果的时间戳实际覆盖到哪里。遇到空结果或覆盖不完整的结果时，存在把未确认尾部当作已完成清除的风险。此次修复针对这一风险，不代表已证明它是用户所述所有漏字的唯一原因。

## 改动

- 每次识别输入最多 8 秒；推理变慢时不会把积压的 18 秒一次当作单个窗口送入。
- 最终结果只消耗时间戳已覆盖的前部音频，未覆盖的含声音频留给后续识别；覆盖末端之后仅可清除已判为低能量的尾部。
- 含声窗口的最终结果为空或缺少有效时间范围时，明确报错停止，避免静默清除这段音频。已有字幕保留，但无法保证得到完整转写。
- 保留 20 秒音频缓冲上限。若识别持续跟不上仍会停止提示，不会通过丢弃旧音频假装跟上。
- Tiny、Base、Small 分别记住路径，切换时自动查找该模型已下载的完整文件。已有完整模型优先本地准备，不再主动走权重下载检查；首次分词器准备仍可能联网。
- 选择文件夹时检查模型型号和必要文件；启动加载后再核对 Core ML 模型实际型号。Small 不再可以悄悄加载 Base。
- 迁移旧路径时按文件夹真实身份登记，不强行绑定到当前下拉框。切换型号清除过期的“准备完成”文字。

## 已验证

发布编译、窗口与音频适配回归、模型文件检查、应用 ZIP 解压与严格签名校验。

回归覆盖：首次 0.5 秒窗口、0.35 秒更新门槛、静音最终结果、推理期间新音频保留、暂停失效、20 秒过载；模拟积压 18 秒输入，只解码 8 秒，若结果仅覆盖 3 秒，则保留其余 15 秒；无效或空覆盖不得推进；型号不符、文件缺失或零字节文件不得标为完整。

## 未完成的真实音频验证

尝试使用 SDK 自带固定英语/日语音频与本机权重。Small 因文件不完整无法加载。Base 可以加载，但推理在当前受限测试环境中创建 Core ML / IOSurface 缓冲时失败，音频解码未完成。因此没有可报告的真实漏字率、识别速度或 Small 与 Base 的对照结果；本次不声称已解决 Whisper 模型本身的漏识别。

## 安装与测试

退出旧版，解压替换 Local Qwen 应用。先在 General 选择 Base，确认显示 openai_whisper-base 路径，再测试同一段普通视频。选择 Small 时若提示尚未准备，点击下载并准备，等待完整下载和加载成功；不要用 Base 文件夹代替 Small。原有纯音频开关和 Qwen 翻译配置保留。

若仍有文字消失，区分原文历史是否缺失、是否出现过载或识别失败提示。临时结果仍可能随新音频修订；“保留输入”不等于 Whisper 不会漏识别、改写或误判背景音。较大的模型也不保证实时性能。

模型目录仍为 ~/Library/Application Support/AirTranslate/WhisperKit/。应用不会在本次代理操作中修改这些权重或用户偏好。

此版为 macOS 26+ Apple Silicon 应用 ZIP，ad-hoc 签名，未获 Apple 公证。源码含本地 SDK 依赖及许可证。
